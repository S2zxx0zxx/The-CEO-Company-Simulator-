## Implementation

R06 Loan decoder; borrow unique ID, positive principal, immutable maturity and rate; proceeds increase cash and liability, not revenue. Credit cap aggregate outstanding principal; interest is separate debt, overdue outstanding loan blocks new borrowing. No automatic maturity repayment or negative cash. Simple noncompounding interest on principal-time, using BigInt denominator periodS*10000, recognize whole-period crossings and maturity stub, aggregate multiple periods mathematically, carry sub-paise numerator across boundaries and partial repayments. Repayment crystallizes any elapsed stub; interest first then principal; no overpayment, no spending reserved cash; fractional remainder below one paise dropped on full payoff. Accrual stops at maturity (no invented penalty), overdue status explicit and can repay later. Active/matured/repaid projection, principal and interest reconciliation, unrecognized interest estimate and payoff, noncash interest-recognition receipt distinct from repayment. Loan maturity is balloon debt due, not a mandatory amortized installment schedule; policy choice to reconcile with original CSV. Rate per simulation period, not annual rate; no assumptions about period length or actual tariffs.
E21 cash >= reserved >= 0, available=cash-reserved; reserve once per ID (zero allowed), release unused or settle actual cost once; overrun may use only genuinely free cash; failed command leaves input unchanged. Direct expense and repayment respect other reservations. Receipt and expense sources share unique source identity; explicit trusted earned revenue/subsidy/fine/resale/equity categories, not arbitrary player-accessible mint. Borrow and repay separate financing receipts. Command identity idempotency: exact same decoded event returns current book unchanged even if stale revision; conflicting payload rejects, new command requires expected revision. Replay strict duplicate history rejection. No journal posting, cash authorization, live scheduler or database CAS here; R29 must derive trusted source receipts, prohibit double posting across expense/reservation and reconcile journal balances, R34/R39 atomic command and receipt integration; R31 insolvency rules. Accrued expense and cash flow must not be counted twice. Book is consistency validated, not save authentication. 10000 event limit, full replay, no measured capacity or archive pruning. All engine time from supplied simulation clock, no Date/random.
