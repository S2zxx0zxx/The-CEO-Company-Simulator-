## Catalog implementation
src/rail/catalog/index.ts: strict version-1 catalog decoder; INR; positive catalog and model revisions, stable model IDs, unique 1..10000 entries, no unknown properties. Powered kinds locomotive, passenger-train, freight-train, mixed-train use existing R06 TrainModel; unpowered passenger-coach and freight-wagon use same canonical gauge, speed, mass, capacity, purchase-price and provenance decoders but no independent traction/range fields. Diesel/electric/steam/dual power types reuse existing traction checks. Reject missing/zero/overflow/fractional mass, range, speed and gauge; unknown/duplicate power, DC 0 Hz distinct from null, incompatible traction electrical attributes. Reject multi-voltage + multi-frequency uncorrelated pairs to preserve R08 fail-closed semantics. Capacity kind rules: locomotive zero seats/cargo, passenger positive seats/zero cargo, freight positive cargo/zero seats, mixed both positive. This is an explicit schema decision; consists and combined payload/mass built later. Price canonical nonnegative 30-digit INR minor units, zero permitted for game starter grants; no market value assertion. Optional nominal energyPerKm records for actual supported modes, positive exact decimal quantity in mL/km diesel, Wh/km electric or g/km steam, unique mode, 0..2 records. Empty or partial list means no nominal estimate supplied for missing modes; R23 actual model and calibration must not treat missing as zero. No calibration claimed.

Each named specification has exactly one field origin (13 powered/8 unpowered). Fictional entries label all fields game-balanced. Real-reference entries require independently reviewed identity/name and at least one specification, other fields explicitly balanced. Price always game-balanced; no fabricated price as fact. Factual field requires a separately supplied trusted evidence record, matching model ID, model revision, field and SHA256 of canonical exact value; evidence includes document SHA256, reviewed UTC and R06 provenance. Evidence bytes and actual reviewer authorization are external trust boundary; code verifies consistency, not truth or independent source ownership. No real catalog records or fact verification introduced. Test-only mock reviews marked synthetic. Canonical ordering for entries, origins, numeric sets, rates and provenance flags; catalog digest includes canonical catalog plus referenced reviews (sorted IDs), so changes in cited document or value change identity; unused review records don't change digest. RollingStockCatalog.prepare builds immutable snapshot and indexed lookup; open requires trusted expected SHA256; resolve exact catalog/model revision and digest; profile returns immutable existing R06 TrainProfile for powered stock, no routing profile for unpowered stock. Reuses R09 digest/freeze helpers and graph ReadonlyTree type, no duplicate graph or route engine; helper dependency catalog -> routing is limited to utilities. Schema only, no persisted catalog registry, roster, UI, purchase/trade, consist calculation or energy simulation.
