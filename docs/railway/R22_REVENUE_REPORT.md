## Implementation
New src/rail/economy/revenue.ts. E04 calculateFare uses exact BigInt rational (base*1000 + distanceM*rateMinorPerKm)*(10000-discountBps)/10000000; floor once, then cap. Zero cap/free fare allowed, no default tariff. E06 calculateCargoRevenue uses kg*metres*rateMinorPerTonneKm*serviceFactorBps/10000000000, floor once; service factor 0..10000 bps (explicit conservative engineering choice, compare original bounds later). E07 delay penalty actual elapsed seconds minus promised positive seconds, floor at zero and cap before 30-digit paise decoding. R06 canonical signed/unsigned decimal units, safe integer counts/time/distance, reject invalid shapes and overflow. Net may be negative. No floating arithmetic.
E05/E06/E07 lifecycle: immutable version-1 RevenueBook with revision, unique trip records, locked fare classes and per-class quantities, cargo consignment IDs/masses/rates/paid distance/service factor, policy SHA, promised duration/penalty terms, segment lengths, R21 trip binding (service, dispatch time, ordered stops and claims). Issue only against reserved R21 trip, check expected revenue+demand revisions, exact allocation sums per OD kind, segment lengths/count and paid distance <= locked OD distance. R10/R34 trusted caller supplies authoritative route lengths and policy hash; no claim that a caller-supplied hash authenticates policy. Store canonical order and reject duplicate trip terms. Settlement requires terminal R21 served/released status, one per trip, exact class receipts paid+unpaid=reserved quantity, refund <= paid gross per class, separate unpaid face value diagnostic (not a duplicate expense), final consignment ID/mass/destination exact, actual arrival >= dispatch, delay capped. Active and paid consignment IDs cannot re-register across trips; released and closed consignment can rebook without double payment. No intermediate transfer receipt receives revenue; full multi-leg consignment transfer/split lifecycle belongs to R33–R35; final delivery event trust required. R21 supports whole trip terminal allocation, so partial delivery is rejected instead of paid incorrectly. Cancellation before revenue recognition yields zero realized revenue; advance payment/refund lifecycle not implemented (R34/R35), no fabricated cash. No separate fine/evasion RNG or inspection collection (R27). Whole-book decoder revalidates demand binding, canonical terms, consignment uniqueness and recomputes stored totals; not save authentication. Pure state candidates; actual combined demand/revenue/cash/energy atomic CAS, replay receipts, journal, archive/pruning and physical arrival integration R29/R34/R35/R39. Limits 10000 records, 1024 class rows and 4096 consignments per trip; fail closed, not measured launch capacity. No UI, real dataset, legacy module or dependency edits.
